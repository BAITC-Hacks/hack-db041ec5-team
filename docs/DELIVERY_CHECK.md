Проверки программные; пяти­минутное выступление и экспертная оценка критериев
не заменяются тестами. Отсутствие ground truth не позволяет заявлять accuracy.

## Команды перед выступлением

```powershell
.venv\Scripts\python.exe -X utf8 run.py --data data --out output/real --config config.yaml
.\start.ps1
```

Проверить status=ok в output/real/run_report.json. В интерфейсе выключить
«Демонстрационный пример» и выбрать output/real в источниках данных.
Если последний расчёт упал, UI теперь не показывает оставшиеся старые файлы
из того же каталога как успешный новый результат.

Обязательные файлы сдачи: исходники A/B/C, requirements-lock.txt, config.yaml,
README и схема, output/real/nodes_roles.csv, clusters.csv, top_nodes.csv.
Для повторного расчёта передать организаторские parquet согласно условиям
хакатона. .env с ключами, локальные окружения и кэши не включать в репозиторий.

## Пяти­минутный сценарий на реальных данных

1. 0:00–1:20 — запустить общий расчёт, объяснить вопрос «кого смотреть первым»,
   открыть отчёт и показать фактическое время завершения.
2. 1:20–2:20 — топ-50 и поиск `100000003115284100`: coordinator,
   priority_score 0,9407 в текущей выгрузке. Показать evidence и реальные
   метрики из карточки; роль — гипотеза, а не доказательство.
3. 2:20–3:10 — найти `100000000404740100`: depth=4, in_sum=25 000,
   out_sum=0, peripheral. Объяснить, почему нельзя объявлять его terminal.
4. 3:10–4:00 — показать кластер, его гипотезу и сравнение изъятий. Не утверждать,
   что наш приоритет всегда сильнее разрушает сеть: в реальном результате
   удаление по степени может сильнее уменьшать LCC. Приоритет решает задачу
   проверки узлов, а не оптимизацию разрушения графа.
5. 4:00–5:00 — офлайн-вопрос «Карточка 100000003115284100», результаты инструмента,
   белые пятна и запросы дополнительных данных. Онлайн показывать только
   после отдельного успешного испытания конкретной модели/endpoint.

Числа взяты из текущей реальной выгрузки. При изменении порогов/данных сверить
их заново; эти gid не используются как правила алгоритма.

## Оставшиеся ограничения

- В описании указано 354 узла с out>in, в данных их 377; оборот отличается
  на 0,01 KZT. Оба предупреждения сохранены, данные не исправлялись под ответ.
- Выводы LLM даже после вызова инструмента требуют сверки; офлайн-ответы
  воспроизводимы. Tool calling и сам текст онлайн-модели без endpoint не проверены.
- Новое Python-окружение проверяется на том же Windows-компьютере; это не
  проверка другой ОС/железа. Перед защитой выполнить команды на вашем ноутбуке.
