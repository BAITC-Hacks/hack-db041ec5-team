# Граф денег — готовая часть C

Интерфейс Streamlit, граф pyvis и AI-ассистент по плану `C_ui_ai(1).md`.
Пакет читает результаты A/B и их функции. Он не присваивает роли, не
меняет приоритеты и не записывает аналитические выгрузки.

**Начни здесь:** распакуй архив, установи зависимости, запусти `app.py`.
Переключатель «Демонстрационный пример» позволяет проверить всё без данных
команды и без API-ключа. Синтетический режим явно отмечен на экране.

## Быстрый старт

Python **3.11 или 3.12**; проверено на Python 3.12. Открой терминал в папке,
где находятся `app.py` и `requirements.txt`.

```bash
python -m venv .venv
```

Активируй окружение:

| Система / терминал | Команда |
| --- | --- |
| Windows PowerShell | `.\.venv\Scripts\Activate.ps1` |
| Windows cmd | `.venv\Scripts\activate.bat` |
| macOS / Linux | `source .venv/bin/activate` |

Если PowerShell запрещает активацию, используй Python окружения напрямую:
`.\.venv\Scripts\python.exe -m pip install -r requirements.txt` и
`.\.venv\Scripts\python.exe -m streamlit run app.py`.

После активации:

```bash
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Открой адрес, который напечатает Streamlit, обычно `http://localhost:8501`.
Чтобы посмотреть пример, включи «Демонстрационный пример» в боковой панели.

Для работы с командой создай `data/` и `output/` рядом с `app.py`.
**Положите файлы в `data/`**: исходные `.parquet` от организаторов.
Результаты A/B положи в `output/`. Альтернативные пути доступны в боковой
панели, в разделе «Источники данных». Нажми «Обновить данные» после выгрузки.

```text
app.py
assistant/               инструменты, модель, офлайн-маршрутизатор
ui/                      загрузчик, граф, карточка, вкладки, стили, демо
tests_c/                 изолированные тесты части C
docs/                    схема, контракт, демо, проверка
.streamlit/config.toml   тема и отключённая телеметрия Streamlit
.env.example            образец переменных окружения
requirements.txt        точные версии прямых зависимостей
```

`moneygraph/`, `run.py` и `config.yaml` принадлежат A/B и **не включены** в
этот пакет. Папки с данными тоже не включены. Часть C работает отдельно;
симуляция удаления подключается к модулю A после интеграции.

## Схема решения

![Схема решения](docs/architecture.png)

A строит граф, метрики и кластеры. B определяет роли, приоритеты и
обоснования. C читает готовые файлы и помогает аналитику исследовать
результаты. Ассистент получает данные только через ограниченный набор
функций; модель не назначает роли и не пересчитывает приоритеты.

## Интерфейс и AI-ассистент

| Вкладка | Возможности |
| --- | --- |
| Обзор | Число узлов, seed, оборот, кластеры, роли, первые 10 приоритетов |
| Граф | Стрелки потоков, цвета ролей/кластеров, размер по приоритету, seed-ромбы, фильтры, поиск gid, окружение 1–3 шага |
| Приоритеты | Выбор строки → эго-граф и карточка; дополнительный выбор gid списком |
| Кластеры | Выбор строки → гипотеза и подграф кластера |
| Устойчивость | Доля крупнейшей компоненты и flow_share по стратегиям удаления |
| Белые пятна | Следующие запросы и скачивание CSV |
| Ассистент | Диалог, фактический режим ответа, список вызовов с аргументами и результатами |

Карточка содержит роль, оценку роли, приоритет, место в топе, шесть баллов
ролей, сработавшее правило, evidence и why, метрики, seed-источники,
контрагентов с ролями, переводы по дням, частоту попадания в топ-20 и
AI-справку. Недоступные значения отмечаются как отсутствующие, а не как нули.

Цвета ролей одинаковы в графе, таблицах, диаграммах и схеме решения.
Подписи на графе — у топ-50 и найденного узла; остальные появляются
в подсказках. Поиск gid показывает его окружение независимо от боковых
фильтров, чтобы фильтр не скрыл нужного клиента.

Граф работает без CDN. Координаты читаются из `graph.json`, физика выключена.
Если `graph.json` ещё нет, граф можно показать по `data/edges.parquet`,
`data/nodes.parquet` и F v0; только временная раскладка считается в C.
Временная раскладка обозначается предупреждением. Роли при этом не
придумываются. Файлы кэшируются по путям, размерам и времени изменения.
При смене набора данных история чата и кэш справок очищаются.

### Офлайн

Работает сразу, без ключа и сети. Используются те же инструменты над графом,
а ответ собирается по шаблону. Поддерживаются:

- «Карточка 900», «Кому платил 900?», «От кого получал 900?»;
- «Кто собирает деньги с этих пятерых: 101, 102, 103, 104, 105?»;
- «Путь от 101 до 920», «Топ-5 консолидаторов кластера 1»;
- «Кластер 1», «Что будет, если удалить топ-3?».

Числа выше относятся **только к демо**. На реальных данных указывай свои gid.
Офлайн понимает перечисленные типы вопросов и не обещает произвольный
диалог. Непонятный запрос возвращает подсказку, а не выдуманный результат.

### Онлайн

1. Скопируй `.env.example` в `.env`.
2. Заполни `OPENAI_API_KEY` и `MONEYGRAPH_LLM_MODEL`.
3. Используй доступную по вашему ключу модель с **Chat Completions и
   function calling**. Модель можно менять в боковой панели.
4. Перезапусти приложение и включи «Использовать онлайн-режим».

Модель намеренно не зафиксирована без проверки доступа вашей команды.
Чтобы получить список доступных имён после заполнения `.env`, выполни:

```bash
python -c "from dotenv import load_dotenv; load_dotenv(); from openai import OpenAI; print('\n'.join(m.id for m in OpenAI().models.list().data))"
```

Присутствие модели в списке само по себе не доказывает поддержку выбранного
endpoint; проверь её документацию и один тестовый запрос в приложении.

Первый запрос требует вызова инструмента. Разрешены только семь функций,
аргументы валидируются JSON Schema. Максимум шесть шагов, ограничения
глубины и размера выдачи, тайм-ауты и отсутствие автоматических SDK-повторов.
При ошибке сети, ключа, квоты, модели или формата ответа приложение
переключается в офлайн и показывает причину без вывода ключа.

Параметр `temperature` не задаётся для совместимости с моделями,
которые его не поддерживают. Точный протокол опирается на
[официальную документацию function calling](https://developers.openai.com/api/docs/guides/function-calling).

Онлайн в API отправляются **вопрос, последние шесть текстовых сообщений и
компактные результаты инструментов**. Сырые `.parquet` и весь граф не
отправляются. Для AI-справки отправляется одна карточка `get_node(gid)` без
истории чата. Ответы справок кэшируются в сессии по набору данных, gid,
модели и режиму. `OPENAI_API_KEY` читается только из окружения; `.env`
исключён из Git. В исходной выборке используются синтетические gid.

Инструменты и осторожный промпт снижают риск выдумок, но не гарантируют
безошибочность текста модели. Рядом показаны исходные результаты для
проверки. Офлайн-ответы детерминированы.

### Семантика анализа

`common_downstream` ищет направленную достижимость от минимум 60%
указанных источников, округляя вверх. Это **не доказательство движения
одних и тех же денег**. Неизвестные gid не исключаются молча: возвращается
ошибка, чтобы не изменить знаменатель.

`money_path` возвращает до трёх путей и минимальный агрегированный оборот
ребра на каждом пути. Он не устанавливает фактическую сумму, прошедшую по
всей цепочке, и не проверяет временной порядок. Есть предел перебора;
неполный поиск помечается. Нулевые исходящие на четвёртом колене не
интерпретируются как удержание денег.

`simulate_removal` вызывает именно `moneygraph.resilience.simulate_removal`
от A, передавая копии графа, F, рёбер и конфигурации. Если модуль или данные
не готовы, возвращается понятное сообщение. В демо расчёт A недоступен;
кривые вкладки «Устойчивость» являются вымышленным примером оформления.

## Подключение к общему проекту

Передай команде **содержимое** папки из архива. В корне общего проекта
должны оказаться `app.py`, `ui/` и `assistant/`, рядом с будущим `run.py`.
Никакие файлы A/B в архиве не подменяются.

Объедините общие `requirements.txt`, `.gitignore` и `.env.example`, если
в репозитории уже есть свои версии. Этот README можно сохранить как
`README_C.md`; в общий README B перенеси разделы «Быстрый старт»,
«Схема решения» и «Интерфейс и AI-ассистент».

Точный формат файлов и контракт симуляции — в [docs/INTEGRATION.md](docs/INTEGRATION.md).
При ручной загрузке через веб-интерфейс GitHub не выбирай `.env`, `data/`
и `output/`: `.gitignore` не фильтрует файлы, выбранные вручную.

## Проверка и демо

```bash
python -m pytest tests_c -q
```

Проверяются направления связей, пороги достижимости, ошибки gid,
ограничения путей, выгрузки, офлайн-намерения, протокол API на тестовом
клиенте, переход в офлайн, изоляция модуля A, запуск и действия в Streamlit.
Это тесты части C, а не проверка корректности аналитики A/B.

- [docs/VERIFICATION.md](docs/VERIFICATION.md) — результаты и границы проверки.
- [docs/DEMO.md](docs/DEMO.md) — сценарий и проверка перед выступлением.
- [docs/C_CHECKLIST.md](docs/C_CHECKLIST.md) — соответствие задачам C1–C7.

Полный прогон `python run.py --data data --out output` и репетиция на
реальных данных выполняются после объединения кода команды. Доступ к
репозиторию и данные хакатона для подготовки этого пакета не предоставлены.
