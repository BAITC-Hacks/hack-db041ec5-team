# Проверка данных организаторов и соответствия ТЗ

Проверены data/data/*.parquet, docs/DATASET.md, starter/starter/README.md,
starter/starter/starter.py и исходное ТЗ. Дата: 23.09.2026.

## Совместимость

Схема и типы всех трёх parquet соответствуют описанию организаторов.
Переименование колонок не требуется. Архив распакован с лишним уровнем data/;
загрузчик теперь поддерживает и data/, и data/data/ без изменения файлов.
__MACOSX не используется. Data и архивы данных исключены из Git.

Оригинальный starter успешно выполнен с выходом в output/starter-reference.
Это каркас: роли, кластеры и топ в его CSV намеренно пустые. Наш пайплайн
заполняет их. Автотест сравнивает реальные in/out степени, суммы, количества
транзакций и frontier с basic_features из starter — совпадают.
PageRank напрямую не приравнивается: starter исключает 19 изолятов из графа,
наш граф их сохраняет, поэтому нормировка PageRank отличается.

Есть два расхождения с числовым описанием ТЗ, которые не скрываются:

1. Узлов с out_sum > in_sum — **377**, а не 354. Из них seed — 42,
   не-seed — 335. Проверка с допуском 1 KZT не меняет число: это не погрешность

   если данное число используется при проверке.
2. Оборот — **365 890 012,01 KZT** против целого 365 890 012 в ТЗ.
   Расхождение 0,01 KZT согласуется с округлением описания; реальные суммы
   не округляются ради совпадения с текстом.

## Результаты анализа

nodes_roles.csv содержит 2 248 уникальных gid, без пропусков обязательных
полей; top_nodes.csv — 50 строк; clusters.csv — 48 строк, включая кластер
изолятов. Девять неизолированных кластеров содержат несколько seed.
Восемь сообществ из примечания ТЗ — ориентир базового Louvain, не обязательное
фиксированное число: наша проекция использует log1p сумм, возможны отличия.

| Роль | Узлов |
|---|---|
| peripheral | 1 434 |
| terminal | 614 |
| transit | 93 |
| coordinator | 62 |
| distributor | 30 |
| consolidator | 15 |

Все 444 frontier — peripheral; ни один не назван terminal. Все 19 изолятов
сохранены. У seed pass_ratio не используется. Все шесть ролей представлены.
Средний Jaccard топ-20 при 200 вариантах весов — **0,9382**.
Атрибуция исходной сети сошлась за 139 итераций, неатрибутированный остаток
примерно 0,000013 KZT. Это вычислительная точность, не доказательство роли.

Первый полный запуск со всеми extras: **63,77 с**, лимит ТЗ — 300 с.
В некоторых сценариях изъятия лимит 200 итераций достигался раньше заданной
точности; max_iter в config.yaml увеличен до 1000 без изменения tol.
Повторная проверка со всеми сценариями прошла без RuntimeWarning о сходимости.
Окончательное время и конфигурация находятся в output/real/run_report.json.

Финальная проверка после всех исправлений: **50 passed, без пропусков**,
99,80 с на весь набор тестов. Реальный полный пайплайн — **73,14 с**.
Два UserWarning соответствуют описанным расхождениям с ТЗ; предупреждений
о несходимости нет. Проверенные финальные артефакты сохранены в output/real.

## Исправления по результатам работы с реальными данными

- Загрузчик и реальные тесты распознают вложенное data/data/.
- Увеличен предел итераций для сценариев изъятия; исходная атрибуция по-прежнему
  останавливается сразу по сходимости, не выполняет все 1000 шагов.
- Реальные gid порядка 10^17 больше Number.MAX_SAFE_INTEGER JavaScript.
  Узловые id и source/target в graph.json теперь строки. В CSV сохраняется
  требуемый int64. UI должен искать строку gid без Number/parseInt.
- Добавлены тесты сравнения с starter, лимита времени на реальном наборе,
  сходимости, граничных ролей, сохранности идентификаторов и целостности JSON.
- README и описание ролей согласованы с текущими ограничениями frontier.

## Статус относительно ТЗ

Пайплайн, обязательные CSV, роль/баллы/объяснение каждому узлу и кластеризация
подтверждены на предоставленных данных. Формальные правила и масштабирование
задокументированы. Выгрузки доступны в output/real, команда запуска:

```powershell
.venv\Scripts\python.exe -X utf8 run.py --data data --out output/real --config config.yaml
```

Пункт 5 выполнен частично: топ есть, интерфейса схемы сети с направлениями,
ролями, кластерами и поиском gid пока нет. graph.json сам по себе не экран.
Также остаются проверка на чистой машине, экспертная оценка порогов и
репетиция живого демо на 2–3 узлах с быстрым разбором произвольного gid.
Обучение модели и AI-ассистент не являются обязательными требованиями.
Starter не требуется копировать поверх рабочего кода: он использован как
независимый ориентир проверки базовых метрик и форматов.
