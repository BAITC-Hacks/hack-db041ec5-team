## Вывод

Аналитическое ядро реализовано и проверено на синтетике. Полное решение пока
не готово к приёмке: отсутствует обязательный интерфейс просмотра и нет
подтверждения на данных организаторов. Обучать ML-модель по этому ТЗ не требуется.

веб-страница, notebook или desktop; Streamlit и LLM не обязательны.
Сохранение graph.json не заменяет экран и поиск.

## Формат результатов

Схемы moneygraph/export.py совпадают с разделом 5:

- nodes_roles.csv: gid, role, role_score, cluster_id, priority_score, evidence.
- clusters.csv: cluster_id, n_nodes, n_seed, sum_kzt_internal, top_gids, hypothesis.
- top_nodes.csv: rank, gid, role, priority_score, why.

Тесты проверяют типы идентификаторов, диапазоны баллов, длину объяснений,
согласованность приоритетов, покрытие узлов и кластеры. На графе меньше 20 узлов
код возвращает всех; на целевом объёме штатный config.yaml даёт 50 строк.
Выгрузки для сдачи должны быть получены из реальных parquet, синтетические
файлы не являются результатом решения кейса.

## Обучение и ограничения

Раздел 6 прямо говорит об отсутствии ground truth и оценке обоснованности,
а не accuracy. Разделы 7 и 9 допускают формальные правила и интерпретируемые
признаки. ML упомянут как один из способов опциональной детекции аномалий;
AI-ассистент — тоже опция раздела 8. Отсутствие обучения и LLM не нарушает
must-have. В критерии технической реализации AI/agentic AI упомянут среди
оцениваемых технологий, поэтому ассистент может усилить решение после закрытия
обязательных требований.

В коде нет списков «правильных» gid; атрибуты личности не выдумываются;
основной пайплайн работает локально без платного API/GPU. Тест произвольной
замены gid проходит на тестовой сети. role_score корректно описан как
эвристический балл, а не измеренная вероятность. Проверка реальных ролей
экспертом и калибровка порогов остаются необходимыми для обоснованного демо.

## Артефакты и документация

Код пайплайна и README есть; исходников интерфейса нет. README содержит
команду запуска, схемы, ограничения и масштабирование до миллиона узлов.
Mermaid-диаграмма есть, но заканчивается CSV/graph.json: после подключения
интерфейса нужно довести её до цепочки «данные → метрики → роли → интерфейс».
Отдельный PowerPoint не обязателен: ТЗ допускает диаграмму.

README и docs/roles.md пока отстают от последнего исправления: условия
distributor/coordinator должны явно исключать frontier. Это выбранное командой
консервативное правило, а не дословное требование ТЗ ко всем ролям frontier.
Фразу README «Пороги исходные из задания» следует уточнить: ТЗ содержит примеры
диапазонов, но не предписывает наши min_in_deg=5, min_out_deg=10 и прочие
точные пороги. Это проектные эвристики, которые надо обосновать.

Демо из раздела 10 ещё не подтверждено: нужны живой прогон и содержательный
разбор 2–3 узлов за 5 минут. Для пункта 3 также нужен быстрый разбор любых gid,
которые назовёт жюри, а не только заранее выбранных примеров.

## Подтверждённые проверки

Последний полный набор: 46 passed, 1 skipped (реальные parquet отсутствуют).
Полный A/B с исходным config.yaml и всеми extras на синтетике
2 248 узлов / 3 119 рёбер / 4 840 транзакций: 16,82 с.
Синтетическая сеть для замера ациклическая; время реального графа может отличаться.
Эти результаты подтверждают работоспособность тестовых сценариев, не accuracy
и не готовность ко всем условиям приёмки. Код проверялся на Windows/Python 3.12,
чистое окружение жюри пока не воспроизводилось.
