## 4. Как объяснять роли и приоритет

Пороги — проектные эвристики из `config.yaml`, а не предписанные организаторами «правильные ответы».

| Роль | Условие кандидата в текущем коде |
|---|---|
| consolidator | ≥5 разных плательщиков; балл учитывает их число, seed-источники и равномерность входов |
| distributor | Не граница выборки; ≥10 получателей |
| transit | Не граница; входящая и исходящая степени ≤3, исходящие >0; для не-seed out/in от 0,8 до 1,2; для seed отдельная поправка |
| terminal | Не граница; вход ≥медианы положительных входов; нет исходящих либо для не-seed out/in≤0,2 |
| coordinator | Не граница; минимум 2 из 3 сигналов: сходимость seed, ролевые соседи, мостовая позиция/несколько кластеров |
| peripheral | Ни одно правило не сработало |

Сначала выбирается лучшая допустимая базовая роль; затем coordinator может её заменить. Поэтому наличия пяти плательщиков недостаточно, чтобы итоговая роль обязательно была consolidator. Полные формулы, равенства и поправки описаны в `docs/roles.md`.

Приоритет: 0,35 × перцентиль seed-оборота + 0,20 × перцентиль числа seed-источников + 0,15 × максимум перцентилей PageRank/betweenness + 0,30 × вес роли × role_score. Для seed итог умножается на 0,85. Веса ролей и остальные параметры находятся в конфиге; вклады `contribution_*` сохраняются для объяснения позиции.

`role_score` — эвристический балл, не вероятность виновности и не измеренная точность. Отсутствие ground truth прямо предусмотрено ТЗ: обучение модели и accuracy не являются обязательными.

## 7. Как самому проверить весь проект

### Шаг 1. Окружение и данные

Откройте PowerShell в папке проекта. Для воспроизведения с нуля используйте установленный Python 3.12 и новое окружение; не копируйте чужую `.venv`.

```powershell
Set-Location 'C:\Users\legez\Desktop\aitu works\Hackathon'
py -3.12 -m venv .venv-check
.\.venv-check\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv-check\Scripts\python.exe -m pip check
```

Если команда `py` отсутствует, используйте путь к установленному Python 3.12. Если в выбранном окружении нет pip, выполните `python.exe -m ensurepip --upgrade` именно его интерпретатором и повторите установку. Установка требует доступного источника пакетов или локального кэша; успех установки на новом компьютере проверяется отдельно.

В `data/` либо `data/data/` должны лежать `nodes.parquet`, `edges.parquet`, `transactions.parquet`. Без них синтетические тесты и демо не подтверждают решение конкурсного кейса.

### Шаг 2. Полный расчёт и три обязательных файла

```powershell
.\.venv-check\Scripts\python.exe -X utf8 run.py --data data --out output/self-check --config config.yaml
if ($LASTEXITCODE -ne 0) { throw 'Расчёт завершился ошибкой' }
$auditReport = Get-Content output/self-check/run_report.json -Raw | ConvertFrom-Json
$auditReport | Select-Object status, elapsed_seconds, n_nodes, n_edges, quality_warnings
if ($auditReport.status -ne 'ok' -or $auditReport.elapsed_seconds -ge 300) { throw 'Проверка статуса или времени не пройдена' }
Import-Csv output/self-check/nodes_roles.csv | Measure-Object
Import-Csv output/self-check/clusters.csv | Measure-Object
Import-Csv output/self-check/top_nodes.csv | Measure-Object
```

При неизменных данных и конфиге ожидаются `ok`, менее 300 с, 2 248 узлов, 3 119 рёбер и количества строк 2 248 / 48 / 50. При ошибке не используйте старые выгрузки как новый успешный результат.

### Шаг 3. Все автоматические проверки

```powershell
.\.venv-check\Scripts\python.exe -X utf8 -m pytest -q --durations=5
```

Для текущего кода ожидается **101 passed, 2 warnings**, без failed/errors/skipped. Пропуски означают, что часть проверки не состоялась; в частности, проверьте наличие данных и starter. Время всего pytest не является временем одного расчёта по ТЗ.

Реальные интеграционные тесты сами повторно рассчитывают выгрузки во временной папке и проверяют: схемы, int64 gid, заполненность и длину evidence, допустимые роли и баллы, покрытие кластеров, топ, frontier, метрики относительно starter, загрузку UI и поиск настоящего gid. Другие тесты покрывают формулы, ошибки входов, произвольную замену идентификаторов, большие gid и ассистента.

## 8. Что остаётся перед защитой

1. Воспроизвести установку и весь сценарий на ноутбуке выступления. Текущие тесты выполнены в уже существующем окружении.
2. Визуально проверить браузер, стрелки, поиск, читаемость карточек и автономную работу.
3. Отрепетировать объяснение любых трёх gid за минуту и полную защиту за пять минут.
4. Проверить роли вручную: несколько случайных и лучших представителей каждой роли; записать спорные случаи и обоснования. Не называть эвристические роли доказанными.
5. Если демонстрировать онлайн-AI — отдельно проверить живой endpoint и модель. Для обязательных функций это не нужно.
