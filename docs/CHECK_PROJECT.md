## Обычный запуск

1. Дважды нажмите `START.cmd` в корне проекта. Нужен установленный Python 3.12.
2. Если данные лежат в `data/`, дождитесь автоматического расчёта и открытия браузера. Если нет — загрузите nodes, edges и transactions через форму приложения.
3. Отключите демонстрационный режим. Посмотрите Обзор → Приоритеты → Граф. Скачайте три CSV из блока результатов.

Закрытие вкладки не останавливает сервер; остановите его Ctrl+C в окне запуска. Если уже работает старая версия, откройте адрес, который выведен в новом окне запуска: порт может отличаться от 8501.

## Автоматическая проверка

В PowerShell из папки проекта:

```powershell
.\START.cmd -Check
```

Команда устанавливает недостающие зависимости и запускает весь pytest. Реальные данные и starter должны быть на месте: пропущенные тесты не считать успешно выполненными. Два предупреждения на конкурсном наборе ожидаемы: 377 узлов с out>in вместо 354 в описании, оборот отличается на 0,01 KZT.

Альтернатива: `.\.venv\Scripts\python.exe -X utf8 -m pytest -q --durations=5`.

## Ручная проверка на конкурсных данных

1. Обзор: 2 248 участников, 3 119 связей, 4 840 операций, 48 групп.
2. Граф: найти `100000003115284100`. Ожидается coordinator, приоритет около 0,9407, вход 2 160 500 KZT, выход 517 000 KZT. Срабатывают сигналы ролевых соседей и нескольких кластеров. Сверить карточку с `node_features.csv`.
3. Найти `100000000404740100`: peripheral, колено 4, вход 25 000 KZT, выход 0. Обрыв выгрузки не означает удержание денег.
4. Взять третий случайный gid из CSV, найти его и объяснить правило. Никаких специальных списков «правильных» клиентов алгоритм не использует.
5. Переключить раскраску на кластеры. На вкладке «Паттерны» проверить таблицы цепочек, близких платежей и циклов. Суммы на рёбрах включаются отдельно; при наведении сумма видна в подсказке.
6. Скачать CSV и сверить первые строки топа. Длинные gid в Excel импортировать как текст, чтобы избежать потери цифр.
7. После установки зависимостей повторить открытие интерфейса без интернета. Отключите онлайн-режим; расчёты и ответы по правилам должны оставаться доступны.

## Проверка других файлов

Нужна та же схема из README. Форма принимает CSV/Parquet, проверяет ссылки на узлы и согласованность сумм и количества транзакций. Полная сеть — снять ограничение глубины; обрезанная сеть — указать последнее колено. Изменять код под новые gid и даты не нужно.

Автотесты отдельно меняют идентификаторы на 18-значные, даты на другой месяц, суммы и глубину; проводят полный путь загрузка → расчёт → интерфейс для обоих форматов. Также проверяют отсутствие файла, дубликат файла, несовпадающие суммы, временной порядок цепочек и близкие платежи.

Успешный запуск на другой сети подтверждает работоспособность вычислений, но не экспертную пригодность порогов для любого бизнеса. Для другой валюты суммы сначала привести к KZT. На миллионе узлов производительность не подтверждена.

## Что сдавать

Код, README, config.yaml, requirements-lock.txt, диаграмму из README и три свежих CSV из успешного расчёта. Папка output игнорируется Git — выгрузки приложить отдельно. Новые загруженные наборы сохраняются в output/uploads, путь результата показан в приложении.

Подготовьте пятиминутную демонстрацию: расчёт → топ → два подготовленных и один случайный узел → кластер → недостающие данные. Экспертную оценку ролей, замер пользы для AML-аналитика и проверку на чужом компьютере нельзя заменить автоматическими тестами; такие результаты не заявляются.
