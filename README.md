# Граф денег — HackAlem AI

Локальный инструмент для аналитика: признаки ролей узлов транзакционной сети,
объяснимый приоритет проверки, гипотезы кластеров и запросы недостающих данных.
Результаты — гипотезы, а не выводы о виновности.

Части A/B/C объединены. Запуск, демо и установка без интернета: [RUN_WEB](docs/RUN_WEB.md).

## Быстрый старт расчётного ядра

Python 3.12; зависимости частей A/B:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.venv\Scripts\python.exe run.py --data data --out output --config config.yaml
.venv\Scripts\python.exe -m pytest -q
```

В Linux замените `.venv\Scripts\python.exe` на `.venv/bin/python`.
`requirements-lock.txt` фиксирует проверенные версии; допустимые диапазоны
зависимостей описаны в `requirements-b.txt` (включает `requirements-a.txt`).

| Файл в data/ | Обязательные колонки |
|---|---|
| nodes.parquet | gid, depth, is_seed |
| edges.parquet | src, dst, sum_kzt, n_tx, depth |
| transactions.parquet | src, dst, date, sum_kzt |

Идентификаторы итоговых CSV — целые int64, is_seed — bool или 0/1.
Неизвестные концы рёбер, отрицательные суммы, дубликаты gid и неверная схема
останавливают расчёт. Отклонения от ожидаемых размеров датасета дают предупреждения
в `data_quality.md`. Заглушек ядра нет. Проверяйте `status: ok` в
`run_report.json`: после ошибки могут остаться выгрузки предыдущего запуска.
Данные и результаты не включаются в Git.

## Выгрузки

Обязательные CSV: UTF-8 без BOM, без индекса, баллы с четырьмя знаками:

| Файл | Строго фиксированные колонки |
|---|---|
| nodes_roles.csv | gid, role, role_score, cluster_id, priority_score, evidence |
| clusters.csv | cluster_id, n_nodes, n_seed, sum_kzt_internal, top_gids, hypothesis |
| top_nodes.csv | rank, gid, role, priority_score, why |

Топ содержит 50 узлов (или все, если их меньше). Дополнительно:
`node_features.csv` — метрики, 6 баллов ролей, вторичная роль, `rule_fired`,
вклады приоритета и `freq_top20`; `graph.json` — координаты, роли, кластеры,
приоритеты; `next_requests.csv` — следующие запросы.
`cluster_metrics.csv`, `cycles.csv`, `resilience.csv` включаются через `extras`

распределение ролей, диагностику атрибуции и средний Jaccard топа.

## Схема решения и метрики

```mermaid
flowchart LR
  A[Parquet] --> B[Проверка данных]
  B --> C[Граф и атрибуция]
  C --> D[Кластеры и метрики]
  D --> E[Роли и объяснения]
  E --> F[Приоритет и устойчивость]
  F --> G[CSV и graph.json]
```

Степени считают уникальных контрагентов, обороты суммируют sum_kzt.
Эффективное число контрагентов = 1 / sum(доля²).
pass_ratio = out_sum / in_sum не определён у seed, frontier и при нулевом входе.
ext_inflow = max(0, out_sum − in_sum) для не-seed.
PageRank учитывает суммы переводов, betweenness — направленные пути без весов.
Быстрый пропуск — доля исходящей суммы при наличии поступления за предыдущие
2 дня, не сопоставление конкретных переводов.

Haircut-атрибуция распределяет деньги по seed и внешнему источнику пропорционально
составу входящих. Собственная подпитка — превышение исходящих над входящими.
Итерационный расчёт даёт seed_kzt, ext_kzt, число значимых seed_sources
и крупнейшие источники. Значимый источник: ≥ max(10 000 KZT, 1% входящих).
Отчёт сохраняет сходимость и неатрибутированный остаток. Цикл без наблюдаемого
источника не считается автоматически внешними деньгами.
Контракты и подробности A: [docs/A_handoff.md](docs/A_handoff.md).

## Роли и пороги

role_score — эвристический балл, не вероятность. Все настройки — в config.yaml.
ramp(x,a,b) = clip((x-a)/(b-a),0,1).

| Роль | Кандидат | Балл |
|---|---|---|
| consolidator | in_deg ≥ 5 | 0,5 ramp(in_deg,4,12) + 0,3 ramp(seed_sources,1,5) + 0,2 ramp(eff_payers/in_deg,0.3,0.8); frontier ×0,8 |
| distributor | out_deg ≥ 10 | 0,7 ramp(out_deg,8,40) + 0,3 ramp(eff_receivers/out_deg,0.3,0.8) |
| transit | не frontier, степени ≤3, out_sum>0; не-seed pass∈[0,8;1,2] | 0,6 близость pass к 1 + 0,4 fast_pass_share; seed: близость=0,5, итог ×0,8 |
| terminal | не frontier, положительный вход ≥P50 положительных входов; out_sum=0 или не-seed pass≤0,2 | 0,6 удержание + 0,4 ramp(log1p(in_sum),log1p(P50),log1p(P95)) |
| coordinator | минимум 2 из 3 сигналов ниже | среднее нормированных сходимости, ролевых соседей и мостовой позиции |
| peripheral | нет кандидатов | 1 − максимум баллов допустимых активных ролей; frontier ≤0,5 |

Базовая роль — максимум среди кандидатов; при равенстве порядок:
consolidator, distributor, transit, terminal. Второй проход может заменить её
на coordinator. Сигналы: (a) seed_sources≥max(P95,3); (b) ≥2 входящих
соседей consolidator/transit или ≥2 исходящих consolidator/distributor;
(c) ≥3 затронутых кластера или положительная betweenness≥P99.
Нулевая betweenness не даёт мостовой сигнал. Для балла соседей берётся
максимум входящего и исходящего числа. NaN дополнительных метрик не создаёт сигнал.
При P50=P95 объёмный ramp terminal равен 0 на пороге и 1 выше него.
evidence ≤200 символов, с формулировкой «Признаки…»; rule_fired содержит
реальные значения, пороги, кандидатов и баллы.
Подробности и статус проверки: [docs/roles.md](docs/roles.md).
Пороги исходные из задания; калибровка на реальных данных ещё не выполнена.

## Приоритет и устойчивость

```
priority = discount × (0.35 money + 0.20 convergence + 0.15 position + 0.30 role)
money       = percentile(seed_kzt)
convergence = percentile(seed_sources)
position    = max(percentile(pagerank_w), percentile(betweenness))
role        = role_weight × role_score
discount    = 0.85 для seed, иначе 1
```

Вес роли: coordinator 1, consolidator 0,9, distributor 0,8, transit 0,6,
terminal 0,5, peripheral 0,1. Перцентили — rank(method=average,pct=True), NaN→0.
Нулевые метрики получают одинаковый средний ранг: приоритет — относительная
сортировка, не абсолютная оценка подозрительности. При равенстве сохраняется
порядок входных узлов. why показывает роль, два крупнейших взвешенных вклада и флаги.

200 вариантов Dirichlet(50×weights), seed=42: доля попаданий в топ-20 и
средний Jaccard с исходным топом. Dirichlet не ограничен строго ±30%.
Реальные Jaccard и время пока неизвестны; после запуска смотрите run_report.json.
Синтетический тест не доказывает лимит 5 минут на полной сети.

## Кластеры и следующие запросы

Louvain по ненаправленному графу log1p-весов; кластер 0 объединяет изоляты,
включая не-seed. Перед Louvain оркестратор временно заменяет gid позиционными
метками, чтобы строковое представление идентификаторов не влияло на равные
кластеры; в результатах восстанавливаются исходные gid.
Гипотеза выбирает первые два сработавших условия:
сбор от ≥2 seed, coordinator, раздача ≥30 получателям, ≥30% transit,
≥60% frontier. top_gids — пять приоритетных узлов.

Запросы: расширение для frontier с положительным seed_kzt≥P90 или консолидацией;
внешние входящие ≥P75 положительной подпитки; операции ниже 5 000 для топ-20;
наличные и межбанк для terminal и seed без исходящих. n_nodes — полный размер
группы, gids — первые 20 по приоритету. Сценарии изъятия сравнивают приоритет,
степень и случайное удаление.

## Ограничения

| Ограничение | Учёт |
|---|---|
| Исходящие 4-го колена не выгружены | frontier не terminal/transit; уверенность peripheral≤0,5 |
| Входящие seed неполны | pass_ratio не используется, скидка приоритета 0,85 |
| Порог 5 000 KZT, только внутрибанк | запросы данных об иных каналах |
| Нет разметки ролей | accuracy не заявляется; нужна экспертная проверка |
| Взаимозаменяемость денег | haircut — гипотеза без временной последовательности |
| Устойчивость | не доказывает верность роли |

n_clusters_touched включает собственный кластер. Устойчивость кластеров A —
средняя максимальная доля сохранившихся вместе участников. Изъятие пересчитывает
подпитку, flow_share может превышать 1. Поиск циклов ограничен, отсутствие
флага не доказывает отсутствие цикла.

Интегрированы A/B. app.py, ui/ и assistant/ относятся к C и здесь пока отсутствуют.

## Тесты, воспроизводимость, масштабирование

Тесты: роли, frontier/seed, NaN, равенство баллов, coordinator, формула и
устойчивость приоритета, CSV, parquet→экспорт, монотонная замена gid и тесты A.
Реальный тест пропускается без данных. Требование 2 248 строк проверяется
только для датасета организаторов, не зашито в алгоритм.
Общий seed=42: модули A пока фиксируют 42 внутри функций, устойчивость
приоритетов читает config.yaml. Для общей воспроизводимости оставляйте seed=42.

Для миллиона узлов: Polars/DuckDB, партиционированный parquet, CSR/igraph/
graph-tool или распределённый движок, приближённая betweenness, Leiden,
пакетная атрибуция источников либо top-k, инкрементальный пересчёт.
Полный spring-layout, точные центральности и циклы не рассчитаны на этот объём.
Интерфейс должен запрашивать эго-графы и кластеры, не весь граф.

Команда: A (Artyom) — граф и метрики; B (Kostya) — роли, скоринг, выгрузки,
оркестратор и документация; C — интерфейс и AI.
